# 发布更新（GitHub 方案）

目标：改完代码后，用三条命令发一版；用户打开「设置 → 更新」点一下就能升级。

## 一次性准备

### 1. 建仓库并推上去

```powershell
# 在 GitHub 网页上新建一个公开仓库，例如 chatbox-pro（不要勾选 README）
cd F:\Projects\chatbox-pro
git remote add origin https://github.com/你的名字/chatbox-pro.git
git push -u origin master
```

> 仓库里只放源码（`release/`、`node_modules/` 已被 `.gitignore` 忽略），
> 100MB 的安装包**放在 Releases**，不进仓库。

### 2. 装 GitHub CLI（可选，但强烈建议）

```powershell
winget install --id GitHub.cli
gh auth login
```

装好之后，发版就是一条命令传安装包；没装也能用网页手动传。

### 3. 在应用里填更新地址

设置 → **更新** → 更新信息地址，填：

```
https://cdn.jsdelivr.net/gh/你的名字/chatbox-pro@master/update/version.json
```

（jsDelivr 在国内通常比 raw.githubusercontent.com 快；备用地址见脚本输出。）

## 每次发版（三条命令）

```powershell
npm run pack:desktop                                    # 打包
npm run publish:update -- --repo 你的名字/chatbox-pro --notes-file release/notes.txt   # 生成 zip + version.json
# 按脚本输出执行：gh release create …  然后 git add/commit/push update/version.json
```

> 更新说明建议写在 `release/notes.txt`（UTF-8，一行一条）。
> 直接 `--notes "中文"` 在 Windows 命令行里可能变乱码，脚本会提示。

`publish:update` 会：

1. 把 `release\ChatBox Pro-win32-x64` 压成 `release\chatbox-pro-<版本>.zip`
2. 算 sha256、写 `update/version.json`（下载地址指向这次的 Release）
3. 把上一版的记录追加进 `history`（应用里「查看更新历史记录」就读它）
4. 打印 `gh release create` 命令和 git 提交命令

## 版本号怎么改

改两个地方（`web/src/version.ts` 是界面显示用的）：

| 文件 | 字段 | 示例 |
|---|---|---|
| `desktop/package.json` | `version` | `1.0.3` |
| `web/src/version.ts` | `APP_VERSION` | `Ver.01.00.3` |

`publish:update` 读 `desktop/package.json` 生成清单里的 `Ver.01.00.3`，所以两处要一起改。

## 用户那一侧发生什么

```
打开 设置 → 更新
  → 自动请求 version.json（主进程，无跨域）
  → 版本不同 → 弹「发现新版本」+ 更新内容
  → 点「立即更新」
      → 主进程下载 zip 到 %APPDATA%\ChatBox Pro\updates
      → 写 apply-update.ps1（等进程退出 → 解压覆盖 → 重启）
      → 应用退出、脚本接管、几秒后自动重开新版本
```

会话与设置存在 `%APPDATA%\ChatBox Pro`，覆盖安装不会动。

## 常见问题

**下载很慢 / 连不上 raw.githubusercontent.com**
换 jsDelivr 地址（脚本会打印）。jsDelivr 会缓存，更新后可能要等几分钟才刷新。

**用户点检查更新没反应**
1. 设置里的地址是否填了 `version.json` 的完整 URL
2. 浏览器打开这个 URL 能不能看到 JSON
3. JSON 里 `version` 必须比当前版本大（`Ver.01.00.3` > `Ver.01.00.2`）

**Windows 提示「未知发布者」**
因为没有代码签名。可以买代码签名证书，或在文档里告知用户点「更多信息 → 仍要运行」。

**想回退版本**
把 `update/version.json` 的 `version` 改回旧号没用（版本比较会认为没有更新）。
正确做法：发一个版本号更高的修复版，或让用户手动下载旧包覆盖。

## 可选：用 GitHub Actions 自动发版

仓库里已带 `.github/workflows/release.yml`：打一个 `v*` 标签并推送，CI 会自己打包、建 Release、更新 version.json。

```powershell
git tag v1.0.3
git push origin v1.0.3
```

> 这条流水线**没有在真实 CI 上跑过**（本地无法验证），第一次用可能要调。
> 赶时间就用上面的手动三步，稳定可控。
