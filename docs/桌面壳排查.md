# 桌面壳排查记录

目标：双击一个程序 → 直接出现应用窗口，不经过浏览器标签页。

## 结论（已解决）

**打包后的 `ChatBoxPro.exe` 可以正常运行**，双击即开原生窗口，不需要浏览器。

出问题的只有 **未打包的 `node_modules/electron/dist/electron.exe`**：进程秒退，
退出码 `-2147483645`（`0x80000003`，STATUS_BREAKPOINT），连 `--enable-logging` 都来不及写日志。

## 关键对照

| 测试对象 | 结果 |
|---|---|
| `node_modules/electron/dist/electron.exe`（含 `electron desktop`、无参默认 app） | ❌ 秒退，无日志 |
| **打包后的 `ChatBoxPro.exe`** | ✅ 正常，4 个进程，窗口标题 `ChatBox Pro` |
| 另一个 Electron 应用（Cherry Studio 2.0.9） | ❌ 也起不来 |
| DeepSeek Harness（Electron，已打包、已签名安装） | ✅ 正常运行 |
| 记事本 / Edge | ✅ 正常 |

## 判断

本机有东西**专门针对 `electron.exe` 这个未签名的原始运行时**做拦截（按文件名/哈希/DLL 组合）。
依据：

1. 同一份 Electron 引擎，改名打包成 `ChatBoxPro.exe` 就能跑；
2. 另一个未打包的 Electron 应用（Cherry Studio）同样起不来；
3. 已签名、已安装的 Electron 应用（DSH）一直正常。

最可能是**火绒安全软件 6.0.12.3**（`HipsDaemon` / `HipsTray`，装在 `J:\Huorong`）的静默拦截——
它不写防护日志，也不注册到 Windows 安全中心，所以从事件日志看不出来。

已排除的原因：

| 排除项 | 依据 |
|---|---|
| 二进制损坏 | dist 完整（73 个文件，含 `icudtl.dat`、`vk_swiftshader.dll`） |
| Node 模式 | 正常，能打印 `process.versions.electron` |
| Electron 版本 | 45 / 30 两个版本表现一致 |
| `--no-sandbox --disable-gpu --single-process --disable-crash-reporter` | 无效 |
| 宿主注入 `ELECTRON_RUN_AS_NODE` | 已清空，仍失败 |
| 受限令牌 | 经 cmd / explorer / 计划任务启动都失败 |
| WDAC / AppLocker / 代码完整性 | 均未启用（`EnforcementStatus=0`，无相关拦截事件） |
| 系统 ASLR / CFG 加固 | 全部 NOTSET |
| 杀软 | Defender 无记录；火绒不写日志（无法直接证实，但最符合现象） |

## 交付方式

- 应用装在 `%LOCALAPPDATA%\Programs\ChatBoxPro\`，双击桌面快捷方式启动。
- 重新安装：`npm run pack:desktop && npm run install:app`
- 备用的 Edge 应用模式启动器仍保留（`ChatBox Pro.vbs` + `npm run shortcut`），
  在 Electron 万一被拦时可用。

## 如果以后想用开发模式（`npm run desktop`）

需要让火绒放行 `chatbox-pro\node_modules\electron\dist\electron.exe`：
火绒主界面 → 信任区 → 添加文件/目录。放行前开发模式一直会秒退。
