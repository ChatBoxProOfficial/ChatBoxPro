# ChatBox Pro 需求备忘

> 本文件是这份产品的「口径」，任何实现上的取舍先回到这里对齐。
> 最后更新：2026-11-17

## 1. 一句话定位

ChatBox Pro 是一个手机 / 电脑都能用的聊天客户端：**自己填自己的 DeepSeek API Key**，
请求经自己的服务器中转，会话默认只存在设备本地；需要时可以把对话导出，
带到 DSH 里继续处理。

## 2. 用户与成本

- 现阶段基本只有**作者本人**用，发布后可能有个别人用，不做多租户、不做账号体系。
- **不收钱、不做付费功能**。只留一个「投喂作者」入口（外链 / 二维码），自愿，**不送钱不影响任何功能**。
- 成本结构：电费（≈20–40 元/月）+ 开发期自用 token（几十元内）。
  上线后用户各自带 key，**token 成本不落在作者身上**。

## 3. 已经定下来的关键决策

| 决策 | 结论 | 原因 |
|---|---|---|
| API Key 归属 | **用户自带**，开发者不垫付 | 否则开发者会破产 |
| Key 存哪 | 只存在**手机本地**，用不可导出的 AES-GCM 密钥（WebCrypto）加密 | 服务器被攻破也不受影响 |
| 请求路径 | 手机 → 自己的服务器（中转）→ DeepSeek | 拿得到 DSH 的能力；也避免浏览器跨域问题 |
| 中转的纪律 | **Key 不写日志、不落盘**；请求体不落盘 | 日志里出现 key 等于送钱 |
| 会话存储 | 两种：`local`（仅本机）/ `server`（多端同步） | 隐私与同步各取所需 |
| 客户端形态 | 一套后端，多个前端：电脑用浏览器、手机用 WebView 壳（Capacitor） | 不开多套原生代码 |
| 软件名 | **ChatBox Pro** | |

## 4. 两种会话

- **仅本机（local）**：只写 IndexedDB，不上传；换设备 / 清数据就没了。UI 上明确标「仅本机」。
- **同步（server）**：存服务器，多端同步。**尚未实现**，按钮先占位。

> 明确边界：只做「聊天」的两种存储，而不是「两种后端」。

## 5. 对话导出到 DSH

目标：手机上选中对话 → 导出文件 → 拖到电脑的 DSH 里 → 继续聊。

- 导出格式：`chatbox-pro.conversation` v1（自描述 JSON，见 `web/src/exportFile.ts`）。
- **下一步必须先确认** DSH 的 `deepseek-chat-import` 插件实际接受的字段，
  在 `toDshPayload()` 一处做映射，界面与存储不动。
- 已核对本机环境：`@deepseek-ai/dsh` 0.2.2-rc.3；`dsh-deepseek-chat-import` 在该包里是
  devDependency，本机安装目录中**未找到**该包，需要用户确认插件实际安装位置。

## 6. 明确不做（现阶段）

- 用户注册 / 登录 / 多租户隔离 / 额度计费。
- 原生重写聊天列表（先用 WebView + 渲染优化）。
- iOS 打包（Android 跑通之后再说）。
- DSH 账号登录自动计费（官方未开放第三方授权，只有 API Key 一条路）。

## 7. 性能口径

- 已知现象：手机上用**微信内置 WebView** 打开 DSH 页面，本身卡、打开长对话更卡。
- 判断：主要是**容器 + 长列表渲染**，不是网络。
- 做法：流式输出按帧合批、定稿后才渲染 Markdown（流式期间纯文本）、
  消息条目用 `content-visibility: auto`、进会话先只渲染最近 30 条、上滚懒加载。
- 验收：真机 Chrome 里打开 `http://<服务器IP>:8787/`，长会话滚动不掉帧。
